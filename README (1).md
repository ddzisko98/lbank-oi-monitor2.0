# Моніторинг Open Interest CXMTUSDT (LBank) -> Telegram

Скрипт кожні 15 хв відкриває сторінку CXMTUSDT в невидимому браузері
(Playwright), зчитує значення "Позиції" (Open Interest) з відрендереної
сторінки і шле повідомлення в Telegram, якщо воно зменшилось порівняно
з попередньою перевіркою.

Працює на GitHub Actions - безкоштовно, без сервера, без домену.
API шукати не треба - скрипт читає ту саму цифру, що бачите ви на сайті.

## Крок 1. Створити Telegram-бота

1. У Telegram знайти @BotFather, написати /newbot, дати назву.
2. BotFather видасть токен виду 123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx - зберегти.
3. Написати своєму новому боту будь-яке повідомлення (напр. "привіт") - це обов'язково,
   інакше бот не зможе писати вам першим.
4. Дізнатися свій chat_id: відкрити в браузері
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   (підставивши токен) одразу після кроку 3 і знайти в JSON "chat":{"id": ЦИФРИ}.

## Крок 2. Створити GitHub-репозиторій

1. Зайти на github.com (зареєструватись, якщо нема акаунту - безкоштовно).
2. Створити новий репозиторій, наприклад lbank-oi-monitor.
   Краще зробити його ПУБЛІЧНИМ - тоді GitHub Actions безлімітний і безкоштовний
   (у приватних репо є ліміт безкоштовних хвилин на місяць, headless-браузер
   витрачає їх швидше за звичайний HTTP-запит).
3. Завантажити туди файли з цієї теки: monitor.py, requirements.txt,
   .github/workflows/monitor.yml, README.md
   (через "Add file -> Upload files" у веб-інтерфейсі GitHub - без консолі,
   структуру папок .github/workflows GitHub створить сам, якщо перетягнути
   файл із таким шляхом у назві, або створити папки вручну кнопкою "Create new file").

## Крок 3. Додати секрети

У репозиторії: Settings -> Secrets and variables -> Actions -> New repository secret

- TELEGRAM_BOT_TOKEN - токен з кроку 1
- TELEGRAM_CHAT_ID - chat_id з кроку 1

## Крок 4. Перевірити вручну

Вкладка Actions -> workflow "Monitor CXMTUSDT Open Interest" -> кнопка
"Run workflow". За 1-2 хвилини побачите результат у логах: або значення
Positions, або помилку, якщо розмітка сайту не збіглась з очікуваною.

Якщо перший запуск покаже помилку "Не вдалося зчитати значення 'Позиції'" -
надішліть мені текст помилки і, за можливості, скріншот кроку Run monitor
з логів Actions - поправлю регулярний вираз під актуальну розмітку сторінки.

## Крок 5. Готово

Далі workflow запускатиметься сам кожні 15 хв. Періодичність можна
змінити в monitor.yml, рядок cron: "*/15 * * * *"
(мінімальний інтервал GitHub Actions - 5 хвилин, але для headless-браузера
15-30 хв - розумніший баланс швидкості й витрати ресурсів).
